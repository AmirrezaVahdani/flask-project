# راهنمای کمد فیزیکی هوشمند

## حالت فعلی
- حالت پیش‌فرض: mock
- در این حالت کمد به‌صورت شبیه‌سازی شده باز می‌شود و بعد از ۳۰ ثانیه بسته می‌شود.
- برای تست نرم‌افزاری، تنظیم زیر در محیط کافی است:
  - LOCKER_HARDWARE_MODE=mock

## تنظیم برای سخت‌افزار واقعی
### حالت دستوری
- LOCKER_HARDWARE_MODE=command
- LOCKER_HARDWARE_OPEN_COMMAND="/path/to/open-locker {locker_number}"
- LOCKER_HARDWARE_CLOSE_COMMAND="/path/to/close-locker {locker_number}"
- LOCKER_OPEN_DURATION_SECONDS=30

### حالت GPIO (Raspberry Pi)
- LOCKER_HARDWARE_MODE=gpio
- LOCKER_HARDWARE_GPIO_ACTIVE_STATE=1
- LOCKER_OPEN_DURATION_SECONDS=30

### نصب پیش‌نیازهای نرم‌افزاری در Raspberry Pi
- نصب کتابخانه RPi.GPIO (یا استفاده از gpiozero):
  - برای Raspbian/Ubuntu روی رزبری‌پای معمولا با:
    - `sudo apt update && sudo apt install -y python3-rpi.gpio`
  - یا با pip در محیط مجازی (در برخی توزیع‌ها نیازمند هدرهای سیستم است):
    - `pip install RPi.GPIO`
  - به‌عنوان جایگزین بالاتر‌سطح می‌توانید از `gpiozero` استفاده کنید:
    - `pip install gpiozero`

#### نگاشت پین‌های GPIO به کمدها (LED)
- LOCKER_HARDWARE_GPIO_PIN_MAP="1:17,2:27,3:22"
  - شماره سمت چپ = شماره کمد
  - شماره سمت راست = شماره پین BCM رزبری‌پای
  - مثال: کمد ۱ روی پین ۱۷، کمد ۲ روی پین ۲۷، کمد ۳ روی پین ۲۲ روشن می‌شود.

#### راه‌اندازی ساده با یک LED برای هر کمد
- آند LED را از طریق مقاومت ۳۳۰ اهم به پین GPIO وصل کنید.
- کاتد LED را به زمین (GND) وصل کنید.
- اگر فقط یک LED دارید و می‌خواهید آزمایش کنید، می‌توانید فقط کمد اول را برای تست تنظیم کنید.

#### استفاده از یک پین پیش‌فرض برای باز و بسته کردن
- اگر از یک ماژول رله یا دربازکن استفاده می‌کنید که فقط دو پین نیاز دارد:
  - LOCKER_HARDWARE_GPIO_OPEN_PIN=17
  - LOCKER_HARDWARE_GPIO_CLOSE_PIN=27
  - در این حالت یک پین برای باز کردن و پین دیگر برای بستن استفاده می‌شود.

## راه‌اندازی Raspberry Pi برای تست با LED
1. روی رزبری پای، اسکریپت نصب و راه‌اندازی را اجرا کنید:
   - `chmod +x raspberry_pi_setup.sh`
   - `./raspberry_pi_setup.sh`
2. برای اجرای مستقیم برنامه:
   - `source .venv/bin/activate`
   - `python run.py`
3. برای اجرای به‌صورت سرویس در بوت سیستم:
   - `sudo cp locker-service.service /etc/systemd/system/locker-service.service`
   - `sudo systemctl daemon-reload`
   - `sudo systemctl enable locker-service`
   - `sudo systemctl start locker-service`
4. برای بررسی وضعیت سرویس:
   - `sudo systemctl status locker-service`

## آیا باید روی Raspberry Pi کدی بنویسید؟
- خیر، نیازی به نوشتن اسکریپت جدید روی رزبری پای ندارید.
- این پروژه‌ی Flask از قبل شامل کنترل GPIO برای باز و بسته کردن کمدهاست.
- فقط کافی است روی رزبری پای این پروژه را اجرا کنید و پیکربندی محیط را اعمال کنید.
- اگر می‌خواهید دستگاه را به صورت خودکار روشن کنید، می‌توانید بعداً از systemd یا یک اسکریپت راه‌انداز استفاده کنید، اما کد اصلی همین `run.py` است.

## صفحه کیوسک و ورود آزمایشی
- پروژه همین حالا یک صفحه ورود ساده و تستی دارد:
  - `http://<raspberry-pi-ip>:5000/public/kiosk`
- صفحه خروج هم آماده است:
  - `http://<raspberry-pi-ip>:5000/public/checkout-kiosk`
- برای تست کیوسک، کافی است کد ملی موجود در دیتابیس را وارد کنید و دکمهٔ ثبت را بزنید.
- پس از ورود موفق، کمد اختصاص داده شده نمایش داده می‌شود و اگر `LOCKER_HARDWARE_MODE=gpio` باشد، LED مربوط به آن کمد روشن می‌شود.

## سیم‌کشی LED برای ۴ کمد نمونه
- پین‌های GPIO را با شماره‌های BCM به این شکل در نظر بگیرید:
  - کمد ۱ -> GPIO 17
  - کمد ۲ -> GPIO 27
  - کمد ۳ -> GPIO 22
  - کمد ۴ -> GPIO 23
- برای هر LED:
  - آند LED را به یک مقاومت ۳۳۰ اهم وصل کنید.
  - سر دیگر مقاومت را به پین GPIO مورد نظر وصل کنید.
  - کاتد LED را به زمین (`GND`) وصل کنید.
- اگر از ماژول رله استفاده می‌کنید، به جای LED اتصال ورودی رله را به پین GPIO بدهید و خروجی رله را به قفل/موتور بدهید.

## جریان کاری
1. کاربر با کد ملی در کیوسک ورود ثبت می‌شود.
2. یک کمد آزاد به‌صورت تصادفی انتخاب می‌شود.
3. اپلیکیشن رزبری‌پای LED مربوطه را روشن می‌کند تا به‌عنوان باز بودن درب کمد نمایش داده شود.
4. پس از گذشت زمان پیکربندی‌شده، LED خاموش می‌شود و کمد به حالت بسته بازمی‌گردد.

## نکته مهم
- اگر سخت‌افزار واقعی ندارید، حالت mock برای تست و دمو کافی است.
- برای اتصال به رله یا دربازکننده‌ی فیزیکی، باید دستورات یا پین‌های GPIO را مطابق دستگاه خود تنظیم کنید.
